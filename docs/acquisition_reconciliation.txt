Exact file scope and purpose
----------------------------
Config/system_config.py:
  Adds ZIP7 readiness defaults: timeout 180 s, poll 5 s, 6 start attempts,
  10 s retry delay and 60 diagnostic log lines.
  Adds MCC defaults: automatic recovery enabled, 10 reconnect attempts,
  2 s delay, 2 command retries, 30 shutdown attempts with 2 s retry delay.
  Removes CAMERA_POWER_OFF_AT_TEST_END: the old logger.stop() already switched
  the camera off regardless of that toggle. Final cleanup now always requests
  OFF for every enabled controlled output.
  Keeps existing local overrides, including the default keepalive setting False.

Control/camera_keepalive_stream.py:
  Imports the ZIP7 implementation: bash -s/stdin SSH, stale-stream cleanup,
  readiness polling, start retries, detailed failure events, identity checks.
  Additionally converts subprocess SSH timeouts to failed results (code 124),
  allowing readiness retries and higher-level recovery instead of escaping
  before those mechanisms can run. Nonzero SSH status cannot report running.

Control/temperature_control.py:
  Serializes every MCC operation using a controller-level reentrant lock,
  including direct controller users outside TemperatureLogger.
  Classifies connection errors using real ULDAQ numeric codes; individual open
  thermocouples/range faults remain per-probe errors without reconnect storms.
  Releases failed/partial handles, rediscovers the same configured MCC, restores
  DIO directions, output intent and thermocouple configuration, then retries.
  Initial connection explicitly requests OFF on all enabled outputs, including
  camera power; previous code left the initial camera output unspecified.
  Updates requested output state before I/O so retrying OFF cannot restore ON.
  Tracks requested states separately from successful output commands; unknown
  states become null after connection release.
  Re-reads complete temperature snapshots after a connection failure rather
  than returning a partial snapshot with values from two connection sessions.
  Provides connection status and reconnect counters.

Control/temperature_logger.py:
  Serializes background reads with Hall/output operations.
  Waits for its worker to exit before disconnect/release (no five-second race).
  Uses interruptible interval waiting; returns explicit shutdown evidence.
  Adds shutdown/status APIs and connection information on logger errors.

Scripts/run_long_test.py:
  Integrates ZIP7 startup recovery and shared recovery accounting.
  Treats failed keepalive restarts as recoverable camera errors.
  Fails pre-cool if lamp/camera OFF cannot be commanded; does not merely warn
  and then turn the freezer ON.
  Performs resilient all-output shutdown, records connection status before and
  after logger stop and preserves the final shutdown record.
  Marks unconfirmed cleanup unsafe_shutdown and stops the entire repeat
  sequence even when REPEAT_CONTINUE_AFTER_FAILURE=True. A summary write
  failure cannot bypass that stop condition.
  Records KeyboardInterrupt as aborted and cleans up; SIGTERM enters the same
  cleanup path when launched through main(). SIGKILL/power loss cannot do so.

Scripts/run_single_sweep_remote.py:
  Integrates ZIP7 validation of keepalive restart; a stopped keepalive cannot
  silently count as a successful sweep. Failure propagates to camera recovery.

Scripts/test_camera_boot_keepalive.py:
  Imports the ZIP7 attended cold-boot/readiness diagnostic; cleanup now uses
  safe logger shutdown, reports its result and fails on unconfirmed OFF.

Scripts/test_mcc_reconnect.py:
  Adds an attended network reconnect diagnostic with every output latched OFF.
  Reads temperatures/Hall and prints connection state; Ctrl+C performs and
  reports safe shutdown. Does not intentionally turn on freezer/lamp/camera.

tests/test_acquisition_safety.py:
  Adds simulated MCC/SSH/orchestrator regression coverage. No hardware calls.

docs/acquisition_reconciliation.txt:
  This comparison, installation guidance and validation limits.

Shutdown semantics
-------------------
Before shutdown I/O, latch freezer/lamp/camera requests OFF together. Future ON
commands on that controller are rejected, including across reconnects. A fresh
controller is needed for the next repeat.

Attempt freezer, lamp and camera OFF independently. A failed freezer command
must not prevent trying the lamp and camera. Do not require a successful
thermocouple reading to attempt output shutdown. Reconnects use only OFF intent.
Read back each enabled MCC digital output against its configured OFF polarity.

safe_outputs_off_confirmed=true means MCC digital output readback matched OFF.
It does NOT prove relay contacts opened or camera supply voltage is zero.
Disabled outputs are explicitly listed and excluded from that confirmation;
software cannot shut down equipment configured outside its control.
Permanent MCC/network loss is recorded as unconfirmed, never successful.

The runner makes an initial safe-output pass and logger.stop() performs a final
pass after joining the logger thread. The final pass determines the final
confirmation; both records remain available. Each pass allows up to 30 attempts.
Attempt limits are not hard wall-clock deadlines: discovery uses a 5 s timeout,
SDK operations and SSH operations also consume time, and stop waits for in-flight
work. Existing thermal/time cutoffs are checked between operations/sweeps; this
patch does not create an independent real-time thermal watchdog.

Final summary fields:
  final_safe_output_shutdown_record
    safe_outputs_off_confirmed, confirmation_scope, disabled_outputs, attempts,
    connection_status
  logger_stop_safe_output_record
  mcc_connection_status_before_logger_stop
  mcc_connection_status_after_logger_stop
Success temperature records include mcc_reconnect_count. Logger errors include
mcc_connection_status. Legacy separate final_*_off_record fields are replaced
by the combined shutdown record.

  success/error/interrupt cleanup; repeat abort; disk-error abort protection;
  startup recovery accounting; sweep restart failure and lamp/wheel cleanup;
  pre-cool OFF failure; absence of warm-start runner/config symbols.

and its private local_config.py. Prefer a fresh sibling clone for this review:

  cd ~/python_dir/Python_scripts
  git clone --branch codex/acquisition-mcc-safety \
    https://github.com/JcpeNewtec/FreezerTest.git FreezerTest_review
  cp FreezerTest/Config/local_config.py FreezerTest_review/Config/local_config.py
  cd FreezerTest_review

Adjust the old directory path above if your checkout is elsewhere. Continue
using the test PC's existing Python environment/dependencies.
In the copied local_config.py, remove the three obsolete assignments and their
warm-start comments:
  PRECOOL_CAMERA_WARM_START_ENABLED
  PRECOOL_CAMERA_WARM_START_SENSOR_NAME
  PRECOOL_CAMERA_WARM_START_C
Also remove CAMERA_POWER_OFF_AT_TEST_END if present; final OFF is mandatory.
Keep the other private settings (paths, probes, thresholds, keepalive, exposure,
repeat settings) as appropriate. Private settings are not in the review branch.

Run automated checks without touching the equipment:
  PYTHONPYCACHEPREFIX=/tmp/freezertest-check python3 -m unittest discover -s tests -v

Then, while present at the equipment, run:
  PYTHONPATH=. python3 Scripts/test_mcc_reconnect.py
Disconnect only the MCC Ethernet cable for 5–10 s, reconnect, verify readings
resume, stop with Ctrl+C and inspect the final safe-output record/readback.
Then, if keepalive is used:
  PYTHONPATH=. python3 Scripts/test_camera_boot_keepalive.py
Finally run one short complete thermal cycle with REPEAT_TEST_COUNT=1 and inspect
final_safe_output_shutdown_record.safe_outputs_off_confirmed in test_summary.json,
plus physically confirm the camera/lamp/freezer are OFF before unattended use.
